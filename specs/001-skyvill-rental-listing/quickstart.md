# Quickstart: 스카이빌 원룸 임대 홍보 단일 페이지 검증 가이드

이 문서는 구현이 완료된 뒤, 별도 빌드 과정 없이 로컬과 GitHub Pages 양쪽에서 기능이
스펙([spec.md](./spec.md))대로 동작하는지 확인하기 위한 실행 가능한 검증 절차다. 상세 데이터
형식은 [contracts/listing-data.schema.json](./contracts/listing-data.schema.json)을,
필드 의미는 [data-model.md](./data-model.md)를 참고한다.

## 사전 준비

- 저장소 루트에 `index.html`, `styles.css`, `script.js`, `DESIGN.md`, `.nojekyll`,
  `listings/skyville-401/listing.json`, `listings/skyville-401/photos/*`가 모두 존재해야 한다.
- 네이버지도 Client ID가 발급되어 `index.html`(또는 스크립트 로더)에 등록되어 있어야 한다.
  로컬 `http://localhost`와 실제 배포 도메인 둘 다 네이버 콘솔의 허용 도메인에 등록되어 있어야
  지도가 렌더링된다(미등록 시 지도만 비어 보이고 나머지 콘텐츠는 정상 동작해야 함 — Edge Case).
- 최신 Chrome/Edge/Safari 중 하나(데스크톱)와 모바일 브라우저(또는 브라우저 반응형 모드).

## 로컬 실행

빌드 과정이 없으므로 정적 파일 서버만 있으면 된다. 저장소 루트에서:

```bash
python -m http.server 8000
# 또는: npx serve .
```

브라우저에서 `http://localhost:8000/index.html`을 연다.

## 검증 시나리오

### 1. 콘텐츠 렌더링 (User Story 2, 3 / FR-001~004, FR-010)

- [ ] 페이지 최초 진입 시 히어로에 제목("스카이빌"), 부제, 리드문, 요약 스펙(보증금/월세/
      관리비/주차비/층수/면적/입주일/전세대출)이 모두 보인다.
- [ ] 방&옵션 → 주방 → 화장실 → 보안 → 건물 편의시설 → 입지 및 주변환경 → 관리비 →
      신뢰 요소 → 마지막 CTA → footer 순서로 섹션이 나타난다.
- [ ] 각 섹션의 본문 문단이 `listing.json`에 있는 문구와 정확히 일치하며, 한두 줄로 줄거나
      모바일에서 숨겨지지 않는다(뷰포트를 모바일 폭으로 줄여 재확인).
- [ ] `listing.json`의 특정 선택적 필드(`keywords`, `specs`)를 임시로 비워도 페이지가 깨지지
      않고 나머지 정보만 표시된다.

### 2. 사진 자산 (FR-011, Constitution VI)

- [ ] 개발자도구 Network 탭에서 모든 이미지 요청이 `200`으로 로드되고, 도메인이 모두
      로컬/배포 origin(상대 경로)이며 외부 hotlink가 없는지 확인한다.
- [ ] 각 섹션 사진이 1~3장 범위이며 깨진 이미지(alt 텍스트만 보이는 상태)가 없다.
- [ ] 히어로 대표 사진만 즉시 로드되고, 스크롤 전까지 아래 섹션 이미지는 `loading="lazy"`로
      지연 로드되는지 Network 탭 워터폴에서 확인한다.

### 3. 스크롤 인터랙션과 성능 (FR-008, FR-009, 성능 원칙)

- [ ] 데스크톱 폭에서 아래로 스크롤하며 각 섹션이 은은한 fade-up(투명도+약간의 위로 이동)으로
      나타나는지 확인한다.
- [ ] 마우스 휠을 빠르게 굴려도 스크롤이 강제로 특정 섹션에 멈추거나(pin), 화면이 통째로
      전환되지 않는지 확인한다(scroll-snap/휠 가로채기 없음).
- [ ] 개발자도구 Rendering 패널에서 "Emulate CSS media feature prefers-reduced-motion:
      reduce"를 켠 뒤 새로고침 — 모든 섹션이 애니메이션 없이 즉시 완전한 상태로 보여야 한다.
- [ ] Performance 패널로 스크롤을 기록해 fade-up 애니메이션 중 레이아웃(Layout) 재계산이
      발생하지 않는지(transform/opacity만 애니메이션되는지) 확인한다.

### 4. 문의 전환 (User Story 1 / FR-006, FR-007)

- [ ] 페이지 어느 위치에서든 화면 하단에 카톡/전화 문의 sticky 바가 보이는지, 최상단부터
      최하단까지 스크롤하며 확인한다.
- [ ] "전화하기" 버튼 클릭 시 `tel:010-8222-7661` 링크가 실행되는지 확인한다(모바일 또는
      데스크톱 다이얼 앱 연동 확인).
- [ ] "카톡으로 문의하기" 버튼 클릭 시 클립보드에 `ckpark1001`이 복사되고 사용자에게 복사
      완료 피드백이 보이는지 확인한다.
- [ ] 이메일 링크가 `mailto:ckpark1001@naver.com`으로 연결되는지 확인한다.
- [ ] 주소, 카톡 ID, 전화번호, 이메일 어디에도 마스킹(`***` 등)이 없는지 육안으로 확인한다.

### 5. 지도 (FR-005)

- [ ] 입지 및 주변환경 섹션에 네이버지도가 고정 높이(240px) 컨테이너 안에 렌더링되고,
      정확한 주소(서울특별시 성북구 보문동2가 82) 위치에 마커가 표시된다.
- [ ] 네트워크 탭에서 네이버지도 스크립트 요청을 차단(offline 시뮬레이션)한 뒤 새로고침 —
      지도 영역만 비고 나머지 텍스트/사진/CTA는 정상 동작해야 한다.

### 6. 접근성 (FR-013, Constitution IV)

- [ ] 마우스를 사용하지 않고 Tab 키만으로 내비게이션, 모든 섹션 링크/버튼, sticky CTA 바
      버튼, 마지막 CTA 버튼까지 순서대로 포커스 이동이 가능한지 확인한다.
- [ ] 포커스된 요소에 시각적으로 식별 가능한 포커스 링이 보이는지 확인한다.
- [ ] 스크린리더(또는 브라우저 접근성 트리 검사기)로 각 섹션이 semantic 랜드마크(`section`,
      `heading` 레벨 등)로 인식되는지 확인한다.
- [ ] Lighthouse Accessibility 점수를 확인하고 90점 미만이면 지적된 위반 사항을 검토한다.

### 7. 경로 이식성 (FR-014, Constitution III)

- [ ] 저장소를 GitHub Pages 프로젝트 페이지(`https://<user>.github.io/<repo>/`)로 배포한 뒤
      동일한 시나리오 1~6을 재확인해 하위 경로에서도 이미지/데이터/링크가 깨지지 않는지
      확인한다.
- [ ] 페이지 소스에서 `/listings/...`, `/photos/...` 같은 절대 경로가 없는지(모두 `./`로
      시작하는지) 검색한다.

### 8. 재사용성 (FR-015, SC-006)

- [ ] `listings/skyville-401/`을 복제해 `listings/test-listing-2/`를 만들고 `listing.json`의
      값(제목, 스펙, 섹션 문구)만 바꾼 뒤, `index.html`이 참조하는 listing id를 그 폴더로
      바꿔 페이지를 다시 열었을 때 `index.html`/`styles.css`/`script.js`를 전혀 수정하지
      않고도 새 콘텐츠가 그대로 렌더링되는지 확인한다(검증 후 테스트용 폴더는 삭제한다).

## 완료 기준

위 8개 시나리오의 체크리스트 항목이 모두 통과하면 이 기능은 스펙의 성공 기준(SC-001~006)을
충족한 것으로 간주한다.
