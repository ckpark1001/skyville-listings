# Feature Specification: 스카이빌 원룸 임대 홍보 단일 페이지

**Feature Branch**: `001-skyvill-rental-listing`

**Created**: 2026-09-13

**Status**: Draft

**Input**: User description: "\"스카이빌\"이라는 제목의 단일 페이지 원룸(오피스텔) 임대 홍보 웹사이트를 만든다. 서울 성북구 보문동 스카이빌 원룸을 실제 매물 사진과 충분한 한국어 설명 글, 신뢰감 있는 톤으로 소개하며, 카카오톡·전화 문의로 이어지는 것이 핵심 목표다. 대상은 보문역 인근에서 원룸을 구하는 1인 가구, 특히 LH·SH·중기청 전세대출을 활용하려는 예비 세입자다. 히어로, 핵심 요약 카드, 방&옵션, 주방, 화장실, 보안, 건물 편의시설, 입지 및 주변환경(지도 포함), 관리비 포함 항목, 신뢰 요소, 마지막 CTA, footer 고지로 구성된 단일 페이지이며, 각 블록은 소제목·본문 1~2문단(제공 문구 그대로)·사진 1~3장·키워드를 갖는다. 스크롤 경험은 차분한 에디토리얼 방식(은은한 fade-up, sticky 문의 바 유지)이며 pin/scroll-snap/강제 스크롤 등은 금지된다."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 언제든 문의로 연결되기 (Priority: P1)

보문역 인근에서 원룸을 찾는 예비 세입자가 페이지 어디에 있든 카카오톡 또는 전화로 즉시 집주인에게 문의할 수 있다.

**Why this priority**: 이 사이트의 존재 목적은 정보 열람이 아니라 문의 전환이다. 문의 수단이 항상 접근 가능하지 않으면 나머지 콘텐츠가 아무리 좋아도 핵심 목표를 달성하지 못한다.

**Independent Test**: 페이지를 열고 어느 스크롤 위치에서든 하단 sticky 바의 "카톡으로 문의하기"와 "전화하기" 버튼을 탭해, 카카오톡 ID 복사 동작과 `tel:` 다이얼 연결이 각각 즉시 일어나는지로 독립적으로 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 사용자가 페이지의 어느 섹션을 보고 있든, **When** 화면 하단을 확인하면, **Then** 카카오톡·전화 문의 sticky CTA 바가 항상 보인다.
2. **Given** sticky CTA 바의 전화 버튼을 탭했을 때, **When** 클릭/탭이 발생하면, **Then** `tel:010-8222-7661`로 연결되는 다이얼 동작이 실행된다.
3. **Given** sticky CTA 바의 카카오톡 버튼을 탭했을 때, **When** 클릭/탭이 발생하면, **Then** 카카오톡 ID `ckpark1001`이 클립보드에 복사되고 사용자가 복사 완료를 인지할 수 있는 피드백이 표시된다.

---

### User Story 2 - 핵심 조건을 빠르게 확인하기 (Priority: P2)

예비 세입자가 보증금, 월세, 관리비, 면적, 층수, 입주 가능일, 전세대출 가능 여부 등 계약 여부를 결정짓는 핵심 조건을 페이지 상단에서 빠르게 스캔할 수 있다.

**Why this priority**: 조건이 맞지 않으면 세입자는 나머지 상세 설명을 읽을 이유가 없다. 핵심 조건을 먼저 확인시켜야 관심 있는 사용자만 스크롤을 이어가고, 그 시간 동안 신뢰감을 쌓을 수 있다.

**Independent Test**: 히어로와 핵심 요약 카드만 표시된 상태에서 보증금/월세/관리비/면적/층수/입주일/대출가능여부 7가지 값을 모두 찾아 읽을 수 있는지로 독립적으로 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 사용자가 페이지에 처음 진입했을 때, **When** 히어로 영역을 보면, **Then** 매물명(스카이빌), 부제, 리드문, 요약 스펙(보증금/월세/면적/층수/입주가능일/전세대출)이 모두 노출되어 있다.
2. **Given** 사용자가 대출 가능 여부를 확인하려 할 때, **When** 신뢰 요소 섹션을 보면, **Then** 융자 없음, LH·SH·중기청 전세대출 가능, 집주인 재직 정보가 배지 형태로 명확히 표시되어 있다.

---

### User Story 3 - 사진과 설명으로 실제 생활을 상상하기 (Priority: P3)

예비 세입자가 방/주방/화장실/보안/건물 편의시설/입지 및 주변환경 섹션의 실제 사진과 상세 설명을 통해 방문 전에도 생활 모습을 구체적으로 그려볼 수 있다.

**Why this priority**: 사진만으로는 생활 동선, 관리 상태, 안전성 같은 맥락이 전달되지 않는다. 상세 섹션은 계약 결정을 굳히는 역할을 하지만, 문의 전환(P1)과 조건 확인(P2)이 없으면 이 섹션까지 도달하는 사용자 자체가 줄어들므로 우선순위가 그다음이다.

**Independent Test**: 각 섹션(방&옵션, 주방, 화장실, 보안, 건물 편의시설, 입지 및 주변환경)에서 소제목, 제공된 본문 전체, 실제 매물 사진 1~3장, 키워드가 모두 표시되는지를 섹션별로 독립적으로 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 사용자가 "방 & 옵션" 섹션에 도달했을 때, **When** 섹션을 읽으면, **Then** 제공된 본문 1~2문단이 축약 없이 전체 노출되고 관련 실제 사진이 함께 보인다.
2. **Given** 사용자가 "입지 및 주변환경" 섹션에 도달했을 때, **When** 지도 영역을 보면, **Then** 네이버지도가 정확한 주소(서울특별시 성북구 보문동2가 82)와 함께 표시된다.
3. **Given** 데스크톱 사용자가 스크롤하며 각 섹션에 진입할 때, **When** 섹션이 뷰포트에 들어오면, **Then** 은은한 fade-up 효과로 콘텐츠가 나타나되 장면 전체가 강제로 전환되거나 스크롤이 가로채지지 않는다.

---

### Edge Cases

- 매물 데이터 파일(`listing.json`)의 특정 필드가 누락된 경우, 페이지는 깨지지 않고 나머지 확보된 정보만 정상적으로 표시해야 한다.
- 네이버지도 스크립트 로드가 실패(네트워크 차단 등)하더라도 주소 텍스트와 나머지 콘텐츠, 문의 CTA는 정상적으로 노출되어야 한다.
- `prefers-reduced-motion`을 사용하는 방문자는 fade-up 애니메이션 없이도 모든 섹션의 콘텐츠를 즉시 완전한 상태로 확인할 수 있어야 한다.
- 매우 좁은 모바일 화면에서도 하단 sticky 문의 바가 본문 텍스트나 마지막 CTA 버튼을 가리지 않아야 한다.
- 키보드만 사용하는 방문자가 Tab 이동으로 sticky 문의 바의 버튼과 페이지 내 모든 링크·버튼에 도달하고 활성화할 수 있어야 한다.
- JavaScript가 비활성화된 환경에서도 핵심 텍스트 콘텐츠와 `tel:`/`mailto:` 연락 링크는 그대로 노출되어야 한다(지도·fade-up 애니메이션·데이터 fetch만 동작하지 않을 수 있음).

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 하나의 페이지 안에 히어로, 핵심 요약 카드, 방&옵션, 주방, 화장실, 보안, 건물 편의시설(엘리베이터/주차/복도), 입지 및 주변환경(지도+성북천), 관리비 포함 항목, 신뢰 요소, 마지막 CTA, footer 고지 순서로 모든 섹션을 제공해야 한다.
- **FR-002**: 히어로 섹션은 제목("스카이빌"), 부제("보문역 1번 출구 30m 초역세권 · 풀옵션 원룸"), 지정된 리드문, 요약 스펙(보증금/월세/관리비/주차비 여부/위치/층수/면적/입주가능일)을 제공된 문구 그대로 표시해야 한다.
- **FR-003**: 방&옵션, 주방, 화장실, 보안, 건물 편의시설, 입지 및 주변환경, 관리비 포함 항목, 신뢰 요소 섹션은 각각 소제목 한 줄, 제공된 본문 1~2문단 전체(축약·캡션화 없이), 관련 실제 매물 사진 1~3장, 필요 시 정보 키워드 또는 스펙 값을 포함해야 한다.
- **FR-004**: 시스템은 매물 데이터(주소, 보증금, 월세, 관리비, 면적, 층수, 입주가능일, 옵션, 연락처, 사진 경로 등)를 단일 데이터 파일에서 읽어와 페이지를 렌더링해야 한다.
- **FR-005**: 시스템은 입지 및 주변환경 섹션에 네이버지도를 통해 정확한 주소(서울특별시 성북구 보문동2가 82)를 표시해야 한다.
- **FR-006**: 시스템은 카카오톡 ID(`ckpark1001`), 전화번호(`010-8222-7661`), 이메일(`ckpark1001@naver.com`)을 마스킹 없이 그대로 노출하고, 각각 클릭/탭 시 ID 복사, `tel:` 연결, `mailto:` 연결 동작을 실행해야 한다.
- **FR-007**: 시스템은 모바일 화면에서 화면 하단에 카카오톡·전화 문의 CTA 바를 스크롤 위치와 무관하게 항상 고정 표시해야 한다.
- **FR-008**: 시스템은 데스크톱에서 각 정보 블록이 뷰포트에 진입할 때 은은한 fade-up 등장 효과를 적용하되, 섹션별 스크롤 고정(pin), CSS scroll-snap, 휠 이벤트 가로채기, 강제 스크롤 이동 등 장면을 강제로 전환하는 기법은 사용하지 않아야 한다.
- **FR-009**: 시스템은 `prefers-reduced-motion`을 사용하는 방문자에게는 등장 애니메이션을 생략하고 모든 콘텐츠를 즉시 완전한 최종 상태로 표시해야 한다.
- **FR-010**: 시스템은 제공된 본문 문구를 원문 그대로 표시해야 하며, 요약·캡션화·모바일 전용 숨김 처리를 하지 않아야 한다.
- **FR-011**: 시스템에서 사용하는 모든 사진은 제공된 실제 매물·현장 사진만 사용해야 하며, placeholder 이미지, 스톡 이미지, 외부 이미지 hotlink를 사용하지 않아야 한다.
- **FR-012**: 시스템은 footer에 "현재 사진은 같은 구조의 다른 호실 사진입니다" 고지 문구를 원문 그대로 표시해야 한다.
- **FR-013**: 시스템은 semantic HTML 구조를 사용하고, 문의 CTA를 포함한 모든 인터랙션 요소에 키보드만으로 도달하고 조작할 수 있어야 한다.
- **FR-014**: 시스템의 모든 페이지 경로와 이미지 경로는 상대 경로로 구성되어 GitHub Pages를 포함한 정적 호스팅 환경에서 정상 동작해야 한다.
- **FR-015**: 시스템은 매물 데이터 파일과 사진 폴더만 교체하면 동일한 페이지 구조를 다른 호실에도 그대로 재사용할 수 있는 템플릿 구조를 유지해야 한다.

### Key Entities

- **매물(Listing)**: 주소, 보증금, 월세, 관리비(포함 항목), 주차비 여부, 면적, 층수/총 층수, 입주가능일, 전세대출 가능 여부(LH/SH/중기청), 융자 여부, 옵션 목록(가전 등), 연락처(카카오톡 ID/전화번호/이메일), 신뢰 배지(집주인 재직 정보 등)를 포함하는 매물 한 건의 정보 단위.
- **정보 블록(Section Content Block)**: 방&옵션/주방/화장실/보안/건물 편의시설/입지 및 주변환경/관리비/신뢰 요소 각각에 대응하며, 소제목, 본문 문단(1~2개), 관련 사진 참조(경로+대체텍스트), 키워드/스펙 값을 속성으로 갖는다.
- **위치 정보(Location)**: 정확한 주소 문자열과 지도 표시에 사용되는 위도/경도 좌표, 인근 교통·생활 시설 설명을 포함한다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 방문자는 페이지에 진입한 직후(첫 화면) 매물명, 위치 요약, 핵심 가치(초역세권/풀옵션/무융자)를 추가 스크롤 없이 확인할 수 있다.
- **SC-002**: 방문자는 페이지 내 어느 위치에서든 클릭/탭 1회로 카카오톡 문의 또는 전화 연결을 시작할 수 있다.
- **SC-003**: 방문자는 보증금/월세/관리비/면적/층수/입주가능일/전세대출 가능 여부 7개 항목 전부를 10초 이내 스캔으로 확인할 수 있다.
- **SC-004**: `prefers-reduced-motion` 사용 여부와 무관하게 100%의 방문자가 모든 섹션의 전체 텍스트 콘텐츠를 열람할 수 있다.
- **SC-005**: 모바일과 데스크톱 각 뷰에서, 페이지 최상단부터 최하단까지 스크롤하는 전 구간(100%)에서 문의 CTA 바(모바일) 또는 문의 수단(데스크톱)이 항상 접근 가능한 상태를 유지한다.
- **SC-006**: 새로운 호실을 추가할 때 매물 데이터 파일과 사진 폴더 교체만으로 페이지가 재사용되며, 이때 코드(마크업/스타일/스크립트) 변경이 0건이다.

## Assumptions

- 사용되는 모든 실제 매물·현장 사진은 이미 확보되어 있거나 배포 전에 제공될 것이며, 사진 촬영 자체는 이 기능 범위 밖이다.
- 네이버지도 API 사용을 위한 Client ID 발급 및 허용 도메인 등록은 배포 준비 단계에서 이루어지는 운영 작업으로 간주하고, 이 기능의 범위는 지도 연동 구현까지로 한다.
- 카카오톡 문의는 별도 인증이나 딥링크 없이 상담 ID를 노출·복사하는 방식으로 충분하다고 가정한다.
- 최초 배포는 "스카이빌" 단일 호실 기준이며, 여러 매물을 목록으로 보여주거나 검색/필터링하는 기능은 이번 범위에 포함되지 않는다.
- 페이지는 한국어 단일 언어로 제공되며 다국어 지원은 범위 밖이다.
